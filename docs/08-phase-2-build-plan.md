# Phase 2 — Extraction pipeline · Build Plan

**4 weeks.** Exit criterion: _inconsistent evidence tables become structurally impossible._

Written late. Phase 0 and Phase 1 each got a plan before any code; Phase 2's first three slices were built straight off the roadmap in `00-product-plan.md`, and this document was written after them. That is recorded rather than tidied away, because the gap is visible in the work: the field-key immutability rule was in `01-data-model.md` §5 all along and was still missed in the schema slice, then added a slice later. A plan would have caught it.

---

## What "structurally impossible" has to mean

The exit criterion is not "the form validates well". A form is bypassed by an import, a bulk action, a future API, or a bug — and every one of those paths ends in the same tables. So each rule below is a **trigger or a constraint**, and the UI's job is only to explain the refusal in language a person can act on.

The test for whether a rule is done: **remove it and watch assertions go red.** Every rule shipped so far has been verified that way, and the counts are recorded in the BUILD-LOG.

## Week 4 — the evidence table ✅ *shipped, branch `phase-2-evidence`*

This is what the previous three weeks were for. A protocol nobody can read the answers to is a filing cabinet.

| #   | Task                                                    | Done when                                                        |
| --- | ------------------------------------------------------- | ---------------------------------------------------------------- |
| 4.1 | Evidence table: papers as rows, fields as columns        | 300 × 20 renders inside the 3 s budget measured in the Phase 1 trial |
| 4.2 | Filter, sort, group — server-side                        | Sorting a NUMBER column sorts numerically, not lexically          |
| 4.3 | **Cell → source**                                        | A quoted cell opens the paper at its anchor; a `BROKEN` anchor says so |
| 4.4 | CSV and XLSX export                                      | Column headers are the field **keys**, which is why they are immutable |
| 4.5 | Unanswered cells are visibly holes                       | An incomplete extraction never looks complete                     |
| 4.6 | Coverage per research question                           | `ProtocolField.questionId` finally used: which questions no included paper answers |

**The export is the reason for several earlier decisions.** Values are plaintext so the database can sort and pivot them; numbers are numbers so a column can be averaged; keys are immutable so two exports of the same review agree about what a column is called. If the export is wrong, those decisions bought nothing.

## Deferred to 2b — *after real usage, per R-06*

Dual extraction and reconciliation: two independent extractions, a diff view, a verifier who resolves, Cohen's κ reported. `Extraction.reconciledFrom`, `verifiedBy` and `IN_CONFLICT`/`RECONCILED` already exist so this needs no migration.

Gated to `SYSTEMATIC_REVIEW`, and deliberately sequenced behind a real thesis student using the loose path first — the rigorous path is a strict superset, so the ordering costs nothing and the alternative is building reconciliation for a workflow nobody has exercised.

## Definition of done for Phase 2

- [x] Every integrity rule is a trigger, and each has been verified by removing it
- [x] `pnpm guards`, `pnpm db:test`, e2e and axe green
- [x] An evidence table for 300 papers × 20 fields renders within budget — 51–56 ms in the database against a 3 s budget. Page-level render is NOT measured; see BUILD-LOG.
- [x] CSV export opens in Excel and Sheets with the right column headers — headers are field keys, asserted end to end. Excel itself is untested; the format is verified by `unzip` and by RFC 4180 unit tests.
- [x] A cell with a quote opens the paper at the passage it came from — and a BROKEN anchor says so, in the reader where the truth is known
- [x] The BUILD-LOG entry exists, with its Problems section non-empty

**Not in Phase 2:** dual extraction, Google Sheets sync, the PDF pipeline, LaTeX.

## Standing practice, carried from Phase 1

- **The security boundary lands before anything writes through it.** Schema and RLS first, UI second.
- **Every negative assertion gets a mutation check.** A `count(*) = 0` that would pass against an empty table proves nothing.
- **A rule is not done until it has been seen to fail.** Drop the trigger, watch the tests go red, restore.
- **Use `Edit` rather than scripted string replacement** for anything that must land. Three scripted edits have silently no-opped in this project while reporting success; `Edit` fails loudly.
- **Run the local gate before pushing, and do not block on CI.** `pnpm guards` runs the same checks CI does.
